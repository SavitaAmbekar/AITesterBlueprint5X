1. Scope & objectives

Objective: verify that the two new login options are visible in the specified location; that eligible users can authenticate using the configured SSO or a registered passkey; and that error, fallback, compatibility, security, responsive, and accessibility behavior is acceptable before QA sign-off.

In scope

  • “Sign in using SSO” and “Sign in with Passkey” buttons and their placement below “Sign in with Google.”
  • Successful and failed SSO authentication, including error handling.
  • Passkey login for users with a registered passkey and fallback guidance when none is available.
  • Unsupported browser/device behavior, responsive UI, accessibility, and compatibility with supported identity providers.
  • Verification that OAuth/SAML/WebAuthn security protocols are followed for the configured flow.

Out of scope (per ticket)

  • Passkey registration flow.
  • SSO provider configuration.

Testing assumes providers and passkey test accounts are already configured and available in staging; this prerequisite requires confirmation.

Requirements and Jira context

Description: Users can log in using “Sign in using SSO” and “Sign in with Passkey.” Both options appear below the existing “Sign in with Google” button and should provide a seamless, secure login experience.

Acceptance criteria:

  1. Both new login buttons are visible and placed below “Sign in with Google.”
  2. SSO login authenticates users correctly and handles errors.
  3. Passkey login authenticates users when registered; fallback guidance if no passkey is available.
  4. Proper error messages for failed authentications and unsupported devices.
  5. Compatibility with supported browsers/devices and identity providers.
  6. Security protocols followed (OAuth/SAML/WebAuthn).

Jira-listed test scenarios: verify button visibility and position; validate successful and failed SSO login; validate passkey login and fallback behavior; check unsupported browsers/devices; test UI responsiveness and accessibility.

Definition of Done: feature implemented and deployed to staging; all acceptance criteria fulfilled; QA sign-off completed; no high or critical defects; documentation updated.

Other ticket metadata: components, labels, fix versions, sprint, linked issues, and attachments are not populated in the issue data. Resolution is unresolved. Estimate fields are not specified. Jira issue: SCRUM-5.
